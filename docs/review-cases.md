## Provider contract

The [official submission guide and full field reference](https://developers.openai.com/plugins/deploy/submission#configure-onboarding-review-and-publication) specifies exactly five positive and three negative cases for initial MCP review. ZIP uploads accept partial lists. Imported cases are read-only in the dashboard: edit canonical inventory and re-upload. Credentials and reviewer instructions belong only in the secure dashboard form; `test_credentials` and `reviewer_instructions` are rejected package fields.

For Agent Plugins, emit `extensions.com.openai.review.test_cases.{positive,negative}` and sibling `extensions.com.openai.publication.release_notes`, not fields under `interface`. Plugin-level cases require exactly one MCP server; per-server review declarations are outside this builder's supported subset. Keep `mcp.json` and its `$schema` marker, provider auth and artwork unchanged.

The strict builder subset accepts `openai_review.test_cases`, optional real `demo_recording_url`, and `openai_publication.release_notes`. Cases accept `description`, `prompt`, `tools_triggered`, `expected_behavior`, optional `file_attachment_urls` and `expected_output_url`. Description/prompt are required; positive cases also require tools/behavior. All supplied text must be nonblank, at most 4000 characters; URLs use the existing public HTTPS restrictions and a 1024-character bound, attachments at most eight. These conservative local bounds are not claims of undocumented provider limits. Lists may be partial, with maxima five/three; repository tests require these two offering inventories to have exactly five/three. Unknown fields, credentials and arbitrary extension pass-through fail closed. Other documented provider fields remain unsupported until explicitly implemented and tested. Do not add a placeholder recording or attachment URL.
