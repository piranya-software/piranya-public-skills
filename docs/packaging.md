# Packaging contract

Optional `readme_file` explicitly selects one `products/<lowercase-hyphenated-name>.md` source, never root README or arbitrary files. The source path and bytes are hash-bound in locks. Both providers map those bytes to package-root `README.md`; provenance records the source path in `source.inputs` and output path in `files`. Markdown closure is checked at the output location: use package-root links such as `LICENSE` or declared `skills/...` members, and HTTPS links for repository-only documentation. No links are rewritten or dependencies inferred. Product documents remain canonical; generated plugin READMEs are not independent authoring copies. Omission remains supported and includes no README.

Inventories require `name`, `version`, `description`, `skills` and `connectors`, and optionally accept `author` with a nonempty `name` only. Optional `license` accepts only the SPDX identifier `MIT` and must be paired with `license_file: "LICENSE"`. This explicitly selects only the root LICENSE, subject to the same file safety, size, text and content checks, and binds its bytes in source locks and generated provenance. No arbitrary root files or implicit inclusion are supported. Both provider manifests emit `license`; the selected LICENSE is at each package root. Other fields are rejected. `skills` maps a skill directory name to the exact relative filenames to include, including `SKILL.md`. `connectors` maps stable connection names to concrete public HTTPS MCP URLs; an empty object produces no MCP configuration. Provider is an explicit build argument rather than part of skill content. A future package is another reviewed inventory, not a modification to a Platform-specific builder.

Only UTF-8 `.md`, `.json` and `.txt` skill inputs are supported. Executables and additional dependency mechanisms are unsupported. Optional `assets` explicitly selects flat `assets/<portable-name>.png` files for both providers. No globbing or inferred inclusion occurs. Selected PNGs are limited to 5 MiB each and square dimensions of 48..4096 pixels. The standard-library validator requires noninterlaced 8-bit RGB/RGBA PNGs, checks chunk order, CRCs, complete bounded zlib image data and row filters, and rejects animation and unknown critical chunks. Other PNG encodings are deliberately unsupported. Binary bytes bypass UTF-8 scans and LF normalization; locks, provenance and ZIPs bind the same captured exact bytes. `openai_interface.logo` and `composerIcon` accept only `./assets/<selected-name>.png`; missing or unselected references fail. Optional `claude_icon` accepts only the same explicitly selected bounded `./assets/<selected-name>.png` reference and emits Claude manifest `icon`; it does not change OpenAI metadata. Claude emits neither OpenAI interface field. Input roots and every component are checked without following symlinks or Windows reparse points. Portable filenames exclude traversal, drive/UNC paths, alternate streams, reserved device names, trailing dots and case collisions. Private/internal/secret/credential filenames are rejected. Text files are limited to 1 MiB each, 256 inputs and 16 MiB total. ZIP inspection bounds entries, expanded size and duplicate/case-colliding names and rejects symlink entries. Output is compared byte-for-byte to the exact generated member map before writing.

Markdown inline links, images and reference definitions to local files must resolve to declared package members. Local traversal, even to an otherwise selected sibling skill, is deliberately unsupported: keep references below each skill directory. Anchors and HTTPS links are allowed; other URI schemes, query-bearing local links and absolute file links fail. HTML links and arbitrary prose/code references are not a dependency discovery mechanism; authors must use supported Markdown links and human review must verify closure beyond that syntax. Inventories never follow links or infer extra files. Unknown unselected source files remain excluded, not recursively archived.

The sensitive-content pattern check is a limited heuristic, not a credential detector or semantic privacy clearance. Public suitability requires human review of every allowlisted file and external URL. A private identifier can be perfectly ordinary text and cannot be ruled out by a regex. Do not put private content in these inventories, even if a test passes.

JSON schemas are validated before use; non-fragment `$ref` and `$dynamicRef` values are rejected recursively. Validation uses an empty referencing registry: no network retrieval is available. Schema bytes must match the source/hash record. Claude uses a deliberately restricted documented metadata subset, not a fabricated official Claude schema. Official Agent Plugins allows other MCP transports, but this builder emits only the selected provider's remote HTTP transport.

Snapshot locks include canonical inventory hash, all selected input hashes, builder code and vendored schema/provenance hashes. Paths in locks are portable package-relative names, not host paths. A lock is data, not a trust root: a consumer must obtain the expected lock and builder through an independently reviewed pin. Changing both malicious content and its lock is not prevented cryptographically. Source commit checking is opt-in for local snapshots and mandatory for release candidates, alongside a separately pinned builder checkout.
